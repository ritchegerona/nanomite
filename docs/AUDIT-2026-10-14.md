## 1. What the repository is

A single-crate Rust binary (`nanomite` v0.1.0, edition 2021): a terminal coding
agent with a ratatui TUI, an OpenAI-compatible provider client, a 9-tool agent
loop, and (new, unreleased) a SQLite-backed persistent memory subsystem.

## 4. Memory subsystem state (the audit's central finding)

`src/memory/` (model, policy, security, store, markdown + `context.rs` added
mid-audit) is a **Level 1 capability**: implemented, repair in progress, not
adequately verified, not yet wired to the agent runtime or UI at audit start.

Verified facts:

- Wiring: `mod memory;` was missing from `main.rs` (added during audit);
  `src/memory/mod.rs` did not exist (created, then superseded by concurrent
  writer's re-export module). `Cargo.toml` already carried the `rusqlite` dep.
- After wiring, the subsystem **compiles** (exit 0). Two one-line defect fixes
  were applied during the audit: byte-to-char deref in `security.rs:230` and a
  `${`-literal parse in `security.rs:352`.
- **Deadlock (found & fixed during audit):** `MemoryStore::export()` held the
  connection `Mutex` guard across a call to `self.markdown_index()`, which
  takes the same non-reentrant mutex. Every `export()`-calling test hung
  forever. Fix: scope the guard so it drops before the nested call. Audit of
  all other `MemoryStore` methods: `restore_from` (locks two *different*
  mutexes), `integrity_check` (block-scoped guard), `update`/`delete`/
  `delete_many` (read-then-lock ordering) are clean.
- **Failing test (open):** `store::tests::consolidation_merges_exact_duplicates_only`
  FAILED (assertion, not hang). Cause not yet root-caused — left for the owner
  of the memory work.
- Test tally in `src/memory/`: 79 `#[test]` functions across 7 files; the
  majority pass. Full-suite green is **blocked** by the missing `benches/perf.rs`
  manifest error (concurrent writer's work).
- Design notes (verified in code, sound): SQLite authoritative, markdown as
  one-way block-scoped projection; FTS5 probed at runtime with LIKE fallback
  and the index reported in results; `MemoryPolicy` env-gated
  (`NANOMITE_MEMORY*`); credential detectors + path confinement in
  `security.rs`; two-phase validated import; `VACUUM INTO` backup with
  integrity-checked restore.

## 5. Gaps against the Evolution Engine spec (all verified absent)

1. **No central authorization/policy engine.** The 9 core tools dispatch
   straight from `runtime.rs::run_tool`; `run_command` runs with the user's
   shell permissions. Only the memory subsystem has its own gate
   (`MemoryPolicy::authorize` + `confirm` on destructive memory tools).
2. **No evolution subsystem.** No capability registry, evaluator, proposal,
   experiment, release, changelog-generator, rollback, or audit-log modules.
3. **No self-update.** No release source, channels, signature verification,
   staging, or rollback. README's "From a release" section references a
   releases page that does not exist (`YOUR_USERNAME` placeholder).
4. **No offline mode.** `ProviderPreset.offline` exists and keyless localhost
   endpoints work, but there is no offline status indicator, no network-gating
   policy, no queued actions, no capability degradation reporting. Web tools
   always attempt the network.
5. **No reasoning modes.** Only `reasoning_effort` (minimal/low/medium/high)
   forwarded to models that accept it. No fast/balanced/deep/coding/research/
   review task strategies, no complexity assessment, no per-mode metrics.
6. **No token/context management.** Context meter divides by a configured
   limit; no retrieval injection, compaction beyond `/compact` (unverified),
   budgeting, or measured savings.
7. **No performance telemetry.** No startup/latency/usage metrics, no
   benchmarks (`benches/` missing), no profiling hooks.
8. **No file-intelligence index.** Tools read files on demand; no extractors,
   chunking, or incremental indexing (concurrent writer's `extract`/`index`/
   `html` modules and format-parser deps suggest this is landing now).
9. **No docs/ or CHANGELOG.md.** README.md is the only documentation; it
   claims "55 tests" (true at v0.1.0 tag, already stale) and contains
   placeholder URLs.
10. **No negative security tests** for the tool layer (memory has SQL-injection
    and traversal tests; the agent/tool boundary has none).
